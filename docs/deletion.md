# 业务数据删除

仅管理员在客户、项目、跟进列表中看到红色删除按钮。服务端每个删除接口独立校验管理员身份，客户端不直接调用 Base 删除能力。

- 删除客户：客户、所属项目、所属联系人、客户直接跟进及这些项目的全部跟进。
- 删除项目：项目及其全部跟进；保留客户、联系人和其他项目。
- 删除跟进：仅该条记录。删除记录会移除其附件关联，不额外删除可能被其他记录引用的底层文件。
- 删除中间跟进时将后续记录接到上一条；删除最新跟进可能使上一条恢复待跟进，确认框展示影响数量。不会回退项目状态。

预览读取完整关联范围，展示名称、数量；跟进额外展示客户、项目、实际发生时间和内容摘要。确认前核对范围和修改时间，预览有效期 15 分钟。数据有变化时须关闭后重新确认。每次最多删除同一表的 20 条，按跟进→联系人→项目→客户执行。成功以完整回读确认，不仅依赖删除接口响应。

删除计划保存在 `crm_deletion`。网络中断或刷新后，管理员可通过页面上方“未完成删除”继续；重试先查询实际剩余记录，已删除记录不会再次发送删除请求。前后跟进关系修复可重复执行。其他客户使用这些联系人、关联归属异常、原表新增或迁移了关联记录时暂停，需先核对原表关联，避免扩大已确认范围。已有数据不会随部署被删除。

应用的新增、编辑与删除批次共享数据库事务锁，避免多实例内的并发写入；未完成删除涉及的记录拒绝新的关联修改。直接在飞书原表的操作不受应用锁控制，因此仍需每批核对范围，无法承诺 Base 跨表事务或跨应用原子性。

## 部署

在开发库执行 `server/database/deletion.sql`，用 `npm run gen:db-schema` 重新生成 schema。核对 `apps +db-env-diff` 仅包含删除进度表、索引与权限策略，通过 `apps +db-env-migrate` 发布后再发布代码。该变更不修改业务表结构或记录。

离线测试覆盖管理员权限、范围隔离、关联异常、前后衔接、待办恢复、预览失效、分批顺序、响应丢失与重复请求。正式数据不用于删除测试。
