# 每日跟进简报

沿用通知设置中的启用开关、成员名单和发送时间，每天向每位启用成员发送一份个人简报，即使全部为 0。按建议执行人分发；未指定执行人的事项保留在全员工作台，不分配给任意成员。预览和「发送测试给我」同样按当前账号筛选。

仅统计仍待跟进的记录，四类互斥，按中国时区划分：

| 分类 | 日期范围 |
| --- | --- |
| 已逾期（红） | 今天之前 |
| 今日待跟进（黄） | 今天 |
| 明日待跟进（蓝） | 明天 |
| 其他待跟进（灰） | 后天及以后，或未安排日期 |

每类保留数量，0 项不展示详情。非空类别按日期升序展示最多 5 项，未安排日期排最后，超出提示剩余数量。每项展示客户／项目、下一步行动、下次跟进日期；分类链接进入「我的」对应筛选，底部进入全部个人待办。消息采用彩色圆点搭配分类文字，避免只靠颜色识别。

读取失败记录错误并按原有规则重试，不发送伪装成零待办的消息。保留按日期及接收人去重、发送结果不明确时不自动重发、关闭或修改设置中止旧批次、过时批次不补发的规则。

## 数据库升级

新安装使用 `server/database/notification.sql`。已有环境在开发库执行 `server/database/notification-digest.sql`，仅给发送记录增加 `overdue_count`、`other_count` 两列；用 `npm run gen:db-schema` 生成类型。正式库禁止直接执行 DDL：先用平台 CLI 的 `apps +db-env-diff` 核对只有预期的两项新增列，再通过 `apps +db-env-migrate` 发布结构，之后发布代码。升级不修改客户、项目、联系人、跟进记录、通知配置或历史发送记录。旧记录的新计数字段为 NULL，不能解释成 0。

发送记录中个人明细保存四类数量；批次记录保存全员读取结果。尚未完成读取的记录不展示数量。离线回归覆盖日期边界、分类互斥、数量为零仍发送、个人隔离、明细限制、重复发送保护及读取失败。
